## Findings and fixes (744cb8c)

Corroborated by both reviewers:

1. `keypair_from_str` sliced `hex[i..i + 2]` before checking the length, so a
   63-digit or multibyte `SOLANA_PRIVATE_KEY` panicked instead of erroring.
   Rewrote it to mirror the test's `decode_seed!/1` precedence exactly (JSON
   array, then 64/128-digit hex, else base58 via `bs58` — Codex also noted the
   generator rejected a base58 seed the tests accept).
2. Keypair files and `exports.env` (which holds the recipient ElGamal secret)
   were written at the umask default and chmod'ed afterwards. Added
   `write_owner_only`, which opens with mode 0600 from creation and
   re-tightens an existing file.
3. The shell header documented `confidential [--output-dir DIR]` while the
   code takes a positional `[OUTPUT_DIR]` (and would have used the literal
   flag as the directory). Header corrected.
4. The account-bound ElGamal/AES key derivation was inlined five and three
   times; extracted `derive_elgamal` / `derive_aes` with the address in the
   error text.
5. The test hook accepted any non-empty JSON object, so `{"unused":"x"}`
   "succeeded" and left stale bundle exports in place, and a non-string value
   raised in `System.put_env` instead of flunking. The hook now requires
   `SOLANA_CONFIDENTIAL_*` string exports including both bundle names.

Codex-only, verified and applied:

6. (7/10) `secrets` truncated `~/.secrets` before the replacement was fully
   assembled and swallowed every `grep` exit code, so a read failure could
   have erased unrelated credentials. It now builds the new file beside the
   old one (mode 600), treats only grep's "no lines" exit 1 as benign, and
   swaps it in with one `mv`.
7. (6/10) `build()` rebuilt only when `main.rs` was newer than the binary, so
   the two lockfile pulls in this very range would have kept running the old
   dependency set. Replaced with an unconditional quiet `cargo build`, whose
   own fingerprint covers Cargo.toml, Cargo.lock and the toolchain.
8. (4/10) Sender balances were topped up only in `setup`; after ~80
   wrong-amount settlements `bundles` would fail. `bundles` now calls
   `ensure_available` for both senders before fetching the blockhash.
9. (3/10) Named the `65536` argument to `configure_account`
   (`MAX_PENDING_BALANCE_CREDIT_COUNTER`).

Codex-only, dropped with rationale:

10. (6/10) The hook's flunk messages echo the command's stdout, which would
    expose credentials if an operator-authored hook printed them before
    failing. The hook is operator-controlled and the shipped generator writes
    only public bundle material to stdout (logs and secrets go to stderr and
    the 0600 state dir); hiding the output would remove the one diagnostic
    the operator needs when the hook breaks. Not changed.
